# 外援 kits — owner rules and kit conventions

The rules every hand-authored 外援 / 甄选 kit (`server/sim/content/kits/waiguan/<charId>.js`, one file per operator, the
registry `index.js` generated by `tools/gen-waiguan-kits.mjs`) follows. Kit comments cite them as "REQUIREMENTS §N" and
"KIT_CONVENTIONS N". Operators without a hand kit run the generic skill spec, the generic talents
(`server/sim/content/genericTalents.js`) and the generic summoner (`server/sim/content/genericSummons.js`); DESIGN §27.

## REQUIREMENTS (owner's rules)

1. **Deployment cost (部署费用 / DP) is real.** Per-player DP with a cap and natural regen (`server/sim/Battle.js`
   `flags.dpMax` / `dpPerSec`), the cost paid at deployment, a knocked-out unit waits for DP to redeploy
   (`DOWN_STATE.WAIT_DP`), `battle.addDp(playerId, n)`. Every 外援 skill / talent that gains, refunds or changes 费用 (skills
   of 嵯峨, 可露希尔, 琴柳, 推进之王, 郁金香; talents of 灰烬, 可露希尔, 老鲤, 琴柳, 焰狐龙梓兰, 郁金香) uses these mechanics, the
   way the pool's DP kits do (德克萨斯 冲锋号令·γ型, 焰尾, 砾). Never approximate DP away.
2. **No manual activation.** The engine auto-casts every skill by its official 技能策略 (`server/sim/skills.js` header:
   DEFAULT, SKILL_RANGE, TAKE_DAMAGE, SP_FULL, CUSTOM_RANGE, SEARCH …; the 3 s automatic-operation cooldown of MANUAL
   skills). Each record carries its resolved `trigger` (`tools/build-data.mjs resolveTrigger`). A kit makes each skill fire
   the way the official strategy would in this mode; it fixes the trigger only when it is wrong or unknown (MARCILS2,
   TRY_SEARCH_ALLY_SKILL fall back to DEFAULT) and says so. The pool-only deviations (`TRIGGER_DEVIATIONS`) are not
   extended to 外援.
3. **Approximations.** A mechanic the engine cannot express, or one that does not exist in this mode, takes the closest
   approximation the pool's kits use for similar cases, marked `[ASSUMED]` in a comment with the reason.
4. **Kit headers.** Each kit lists its `[ASSUMED]` readings in its header comment, so the owner can review them in one place.
5. **Consumable summons** (traps, phantoms and similar summons that are used up): each battle gets the official count
   ("可以使用N个…" etc.); once used up there are no more that battle; the stock is refilled at the next round.
6. **Placement.** No module widens placement (PRTS 卫戍协议/帮助 §战斗部署: "携带Y模组的教官仍无法部署至高台位"): elite 帕拉斯
   with INS-Y and 艾拉's trap under TRP-D stay on the ground; only the 歌蕾蒂娅 HOK-Y rule of `shared/highGround.js` exists.
   Kits never change placement.
7. **Modules.** Every 外援 elite carries its operator's modules at its slot's level (tier V level 1, tier VI level 3). Kits
   read every number from the record, never level-3 literals. Mode-scoped module text ("在集成战略中…", "在生息演算中…",
   "在【…】中…") has no battle effect in this mode (pool precedent); marked `[ASSUMED]`.
8. **Settled readings.** 煌 S3's end blast hits her attack range plus the enemies she blocks.

## KIT_CONVENTIONS (from the kit reviews)

1. Damage over time (burn ticks, "每秒…" pulses, zone ticks) is tagged `'dot'` and passes `canDodge: false` (pool: 伊内丝
   S1, kits/tier4.js; consumers of 'dot': 锡人 凋敝魂灵, garrisons, bonds, professions.js).
2. Counter damage ("受到攻击时…造成…"): `canDodge: false` and the `'counter'` tag.
3. Every tag a kit emits is unique to its effect (tests filter on tags).
4. Auras / buffs on allies or enemies follow the strongest-source rule (pool `installAura`): two copies of an operator
   never overwrite or double each other.
5. "Her player" scope: counting or buffing "队伍 / 编入队伍 / 场上" allies uses the owner's player (`unit.ownerId`) for both
   the count and the buff.
6. No literal numeric fallbacks for blackboard keys: a missing key means "not at this module level / not upgraded".
7. Tests lock behaviour: exact first amounts and orderings, guards (attack-only, HP-gated, ground/flyer), scope, redeploy /
   re-arm, every module (incl. 'none') × every skill, both tiers' elites.
8. Where the text is silent, timings / order / lethality follow the official buff templates (`buff_template_data.json` of
   the game data, `gamedata/battle/`); team / group membership comes from `character_table.json`.
9. "攻击被阻挡的敌人" counts an enemy blocked by ANY unit (`target.blockedBy`), as the pool does, unless the text says 自身阻挡.
10. A skill's own target rule follows its text ("至多3个重量最重的敌人"), not the attack selector's blocked-first rule.
11. Ramp templates (`RemainingRatioToAttributeModifier`, "逐渐提升") step once per second like 卡涅利安's S3.
12. An fx radius / shape matches the tiles the effect actually hits.
13. Ground vs flyer follows the template's `targetMotion` (AOEDamage `WALK_ONLY` → ground only).
14. When the owner leaves the field, her summons follow the official templates (`kalts_t_withdraw_token` ON_OWNER_FINISH →
    WithdrawTokens: a withdrawal, not a kill, so no death effects); without such a template the summon stays (赫默's
    医疗探机). A skill "bound" to a summon follows its `sp_cond` template (SP cleared and not recovering while the summon is
    absent), not a cast veto.
15. Module dispatch by `chess.module.type` / module id, never by regexes on the module text.
16. A summon's hand count is its deploy cap (deployLimit + the token's hidden `max_deploy_count`,
    `GameData.placeableTokens`); tests place pieces through that function.

A hand-authored owner kit owns its summons entirely (no generic summon talents, trap / no-attack readings or deploy-limit
policing) unless it sets `genericSummons: true`; then `managedTokenTalents` names the summon talents it implements itself.
