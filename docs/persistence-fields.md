# 对局状态的持久归属

实现入口是 `server/match/checkpoint.js` 和 `worker/room-runtime.js`。Match、Battle 中技能闭包、生成器、共享首领池和临时状态不适合直接 JSON 化。本实现重执行**完整**初始化配置、外部方法调用与定时器执行顺序，重建整个对象图；渲染 snapshot 仅用于核验/回放，不能加载成活跃战斗。

| 状态族 | 持久来源与恢复方式 |
| --- | --- |
| 模式、难度、席位、种子、计时/战斗选项 | checkpoint.options 白名单与原版本内置数据，重新构造 Match |
| 六条随机流 | 相同初始化与调用顺序重执行；显式保存 RNG 末状态并逐条比较 |
| 当前回合/阶段、策略、商店、经济、背包、棋盘、负载、LP、个人统计 | start/handle/setLoadout 有序事件和原版本规则重新执行 |
| PlayerState 的 Map/Set、对象共享、临时增益、技能闭包、召唤及 AI 内部状态 | 原构造器与原技能代码重执行，不从 JSON 恢复函数/对象指针 |
| Battle 单位/位置、波次、射弹、伤害序列、共享首领池、联防映射 | 原 spec、原规则、真实客户端进度/结果和服务端计时事件重执行 |
| 定时闭包与截止时间 | VirtualScheduler 按原注册顺序重建，日志记录触发 ID/时刻；恢复时核验下一个计时器 |
| 人类连接、离开/重连、托管接管 | 有序 onDisconnect/onReconnect/onLeave；DO 唤醒后与仍存活且会话有效的 WebSocket 重新对齐 |
| 对局外房间配置、申请/预留、席位账号、连接 epoch、命令去重、继续票据 | Room snapshot，分块 KV 与 SQL 日志同事务提交 |
| 完成事实、提前离开时的个人事实、录制片段 | 同一持久 Room snapshot 的 outbox；幂等发布至独立 Archive/Account |

恢复过程禁止再次广播旧帧或重复执行外部 onEnd。完成后比较 publicView 和 RNG 状态，不匹配/未知 schema/未知规则则拒绝加载并保留原存储。定时推进单批有上限；历史记录上限 200,000 条用于拒绝无法处理的输入。此上限不是固定恢复 CPU 保证，也不是事件裁剪策略。

与最初计划的差异：没有实现“每五秒可独立执行的模拟状态快照”、命名技能闭包注册表或删除早期事件；完整日志必须保留到对局归档。这样避免不完整快照破坏玩法，但恢复成本随日志增长。规则版本同时保留服务端恢复模块及浏览器回放模块，未来改为固定成本快照需要新的 schema 与旧版本兼容路径。
