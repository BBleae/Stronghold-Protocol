# 对局状态的持久归属

实现入口是 `server/match/checkpoint.js` 和 `worker/room-runtime.js`。Match、Battle 中技能闭包、生成器、共享首领池和临时状态不适合直接 JSON 化。本实现重执行**完整**初始化配置、外部方法调用与定时器执行顺序，重建整个对象图；渲染 snapshot 仅用于核验/回放，不能加载成活跃战斗。

| 状态族 | 持久来源与恢复方式 |
| --- | --- |
| 模式、难度、席位、种子、计时/战斗选项 | checkpoint.options 白名单与原版本内置数据，重新构造 Match |
| 六条随机流 | 相同初始化与调用顺序重执行；显式保存 RNG 末状态并逐条比较 |
| 当前回合/阶段、策略、商店、经济、背包、棋盘、负载、LP、个人统计 | start/handle/setLoadout 有序事件和原版本规则重新执行 |
| PlayerState 的 Map/Set、对象共享、临时增益、技能闭包、召唤及 AI 内部状态 | 原构造器与原技能代码重执行，不从 JSON 恢复函数/对象指针 |
| Battle 单位/位置、波次、射弹、伤害序列、共享首领池、联防映射 | 原 spec、原规则、真实客户端进度/结果和服务端计时事件重执行 |
| 定时闭包与截止时间 | VirtualScheduler 按原注册顺序重建，日志记录触发 ID/时刻；恢复时核验下一个计时器 |
| 人类连接、离开/重连、托管接管 | 有序 onDisconnect/onReconnect/onLeave；DO 唤醒后接回休眠中保持的 WebSocket（登录与其到期时间随连接附件保存，到期本地检查，每分钟后台向账号目录复核）；重启时丢失连接的会话按正常断线处理（Lobby.onDisconnect：单人对局保留 24 小时恢复期，大厅席位的宽限从唤醒时起算） |
| 对局外房间配置、申请/预留、席位账号、连接 epoch、继续票据 | Room snapshot，分块 KV 与 SQL 日志同事务提交 |
| 完成事实、提前离开时的个人事实、录制片段 | 房间的 archive_outbox / archive_chunks 表（对局结束的同一事务写入，编码一次，不进入快照）；幂等发布至独立 Archive/Account，失败按条记录尝试次数与下次重试时间（attempts / retry_at） |

恢复过程禁止再次广播旧帧或重复执行外部 onEnd。完成后比较 publicView 和 RNG 状态。定时推进单批有上限；历史记录上限 200,000 条用于拒绝无法处理的输入。此上限不是固定恢复 CPU 保证，也不是事件裁剪策略。

无法恢复的对局按「中断」结束，房间不会因此损坏（`RoomDurableObject.restoreMatch`）：规则版本不在本次部署内（Cloudflare 回滚）、日志缺行、重执行抛错或状态不一致，以及上一次恢复没有完成（CPU / 内存上限或 30 秒 blockConcurrencyWhile 超时会直接重置对象，不经过任何 catch，所以每次重执行前先持久记一次尝试，第二次尝试直接中断，不再重执行）。中断时：参与者的对局记录写入一条「对局中断」，房间关闭并释放所有席位，玩家重连时收到 room.closed（`rollback`：服务器版本已回退；`restart`：服务器重启后无法恢复本局），检查点与其日志删除，日志输出 `match_restore_failed`（房间、规则版本、事件数、尝试次数、错误）。恢复成功后，尝试计数在房间处理完下一个事件并提交时清除。每次唤醒都要重执行完整日志，所以有人连着进行中的对局时房间不休眠；无人连接的对局休眠到下一个截止时间（对局计时器、重连期限），不为刷新在线大厅列表而唤醒。

与最初计划的差异：没有实现“每五秒可独立执行的模拟状态快照”、命名技能闭包注册表或删除早期事件；完整日志必须保留到对局归档。这样避免不完整快照破坏玩法，但恢复成本随日志增长。规则版本同时保留服务端恢复模块及浏览器回放模块，未来改为固定成本快照需要新的 schema 与旧版本兼容路径。
