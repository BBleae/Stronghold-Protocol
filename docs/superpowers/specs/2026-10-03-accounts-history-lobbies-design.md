# GitHub 账号、跨设备续局、历史回放与公开大厅

日期：2026-10-03。状态：用户已批准设计；实施计划另行审阅，尚未实施。

## 目标与已确认要求

- 使用 GitHub OAuth 标识玩家，同一账号跨设备继续同一对局。
- 长期保存对局历史，玩家能观看自己的对局回放、查看历史统计。
- 主页直接显示有真人在线的大厅，申请加入需要房主批准，开局后不允许新玩家中途加入。
- 用户明确要求：必须完全符合现有设计风格，不改变原有组件的设计风格。这是验收条件。

## 现状与方案选择

现有前端为 Preact/htm，公共组件位于 public/js/ui/components.js，主题位于 public/css/theme.css。账号目前实际是浏览器保存的昵称与重连 token。Workers 按房间使用 Durable Object；worker/room-runtime.js 的 snapshot 在对局进行中只返回标记，不保存 Match。现有 room.replay 仅重发结算帧，不能当作战斗回放。

推荐沿用 SQLite Durable Objects：房间管理当前对局，站点目录管理账号索引与大厅，每场对局独立档案管理记录。账号和历史按用户拆分，避免所有战斗记录集中到一个目录对象。

其他方案：全部历史放在房间对象中，改动较少但房间回收、代码复用和长期查询耦合；引入 D1 加 R2，便于较大规模分析与归档，但增加当前小规模站点的配置和维护。本期选择前述 DO 方案，存储访问集中在适配层，为后续迁移保留边界。

本期完整在线能力面向当前 Cloudflare 站点。原 Node 本地模式保留可运行的旧流程；未配置在线账号能力时不展示无法使用的入口。Node 端接入同等持久化账号服务不包含在本期默认范围。

1. 复用 theme.css 的颜色、字体、层级和动效变量；沿用 1920×1080 设计尺寸对应的 rem 缩放、1px 细线和 150–250ms 动效。
2. 复用 Panel、Button、MicroLabel、Tabs、AvatarFrame、DifficultyTag/图标、Modal、Spinner 和现有 toast；不重设公共组件的背景、圆角、阴影、字体或交互状态。
3. 新 CSS 只补充页面布局与特有元素，使用页面作用域类名，不通过全局选择器改变现有界面。
4. 保留现有标题页与大厅的视觉结构和模式选择。大厅右侧加入公开大厅面板，保留邀请码入口；窄屏沿用现有响应式规则，列表内部滚动。
5. 登录按钮沿用现有主按钮，头像沿用 AvatarFrame。账号菜单提供“继续对局”“对局记录”“个人统计”和退出登录。
6. 房间审批使用现有面板/弹窗：申请人、申请时间、同意/拒绝。申请者看到等待、取消、已拒绝或已失效状态。
7. 历史列表沿用面板与难度标识；详情复用结算卡。统计页复用结算数值排版，避免引入另一套仪表盘组件。
8. 回放复用现有棋盘、角色、特效与战斗 HUD，增加相同风格的回合、玩家视角、播放/暂停和倍速控件；回放中的购买、部署等操作禁用。
9. 实施前后用同一素材、视口和数据比较截图，检查标题、大厅、房间、结算原有组件没有视觉回归；同时验证桌面和手机横屏。

## GitHub 身份与会话

公开站点允许未登录浏览大厅，创建房间、申请加入、续局和查看个人历史需要 GitHub 登录。GitHub 数值 ID 是账号唯一标识，昵称和头像仅用于展示；游戏昵称可独立设置。

使用服务端 authorization-code 流程、一次性 state、S256 PKCE 和固定回调地址。只读取公开用户身份，不申请仓库或邮箱权限。OAuth token 只在服务端完成身份读取时使用，不交给浏览器，也不长期保存。

站点生成随机不透明会话，服务端保存哈希与过期时间；浏览器使用 HttpOnly、Secure、SameSite=Lax cookie。会话有效期默认 30 天，退出登录撤销当前会话。OAuth 临时事务 10 分钟失效且只能消费一次，返回地址只允许站内白名单。

API/WS 从可信会话取得 accountId，不接受客户端自报身份。所有变更接口校验同源与 CSRF，回调失败保留明确重试入口。GitHub Client Secret 通过 Workers secret 配置，开发与正式环境分开注册回调。

旧匿名 token 不能凭昵称自动归属 GitHub 账号。上线后新局使用账号；已有匿名对局不宣称已迁移，首次切换安排在旧局结束后。历史只从新版本开始记录。

## 跨设备与存档

账号记录至多一个有效席位引用（roomId、roomGeneration、matchId、seatId）。主页登录后查询并验证实际房间状态，提供“继续对局”。过期引用在验证后清理。

进入另一设备后由用户点击继续，服务端提升席位连接代次，原连接收到已在其他设备继续的提示并停止发送游戏指令。后续消息都验证连接代次；旧设备的迟到指令和战斗结果不能写入新状态。

沿用现有断线时间规则：同盟掉线期间由既有逻辑接管，独立模拟遵循既有 24 小时恢复窗口；跨设备不意味着冻结其他玩家的游戏或无限期保留席位。

增加明确的 Match 序列化/恢复接口：保存阶段、回合、玩家、商店/卡池、随机数状态、棋盘、盟约、AI、共享首领状态、计时期限、已处理指令序号及必要战斗输入。不得直接 JSON 序列化定时器、WebSocket、函数或循环对象。

已接受操作先持久化再确认；自动阶段转换也必须留下可恢复记录。检查点加有序事件日志负责恢复。恢复时重建调度器，按照绝对期限处理过期动作且只执行一次；客户端重新同步。活跃战斗从战斗检查点及其后的有序事件恢复，不能单靠初始 seed 重演整局。

存档记录 schemaVersion、rulesVersion 与 dataVersion。兼容升级提供迁移；不兼容版本必须保留旧恢复实现或推迟发布，不能默默清除对局。故障恢复验收覆盖休整、普通战斗、联防及最终攻势。

## 公开大厅与审批

目录只显示公开、至少一名真人连接且心跳新鲜的同盟房间；AI 不计入“有人”。显示房主、难度、真人/AI/席位数量、等待或进行中。满员与进行中可见，但申请按钮禁用。独立模拟和私密房间不进入列表。

新建同盟房间默认公开，房主可切换私密；已有房间默认私密。邀请码仍可使用，但同样走审批流程，不能绕过房主批准。

在线房间每 20 秒刷新目录租约，超过 60 秒未续约的条目隐藏；加入、离开、开局、结束和可见性变更主动更新。客户端页面可见时每 10 秒刷新，支持手动刷新，离开页面后停止轮询。

申请状态：pending → approved / rejected / cancelled / expired。每账号同一时间最多一条 pending，120 秒过期；单房间最多 20 条 pending，提交和审批受限流保护。

审批在房间对象串行执行：检查当前房主权限、申请有效、申请者没有其他席位、房间未开局且有空位；不能占用 AI 席位，需房主先移除 AI。审批成功为申请者预留席位 30 秒，连接后生效，未连接则释放。跨对象用申请 ID 和席位声明 ID 幂等协调，不假设跨 DO 事务。

房主更换时申请归现任房主处理。开始游戏、房间关闭或转私密使现有申请失效；并发批准与开局由房间状态顺序决定，申请本身不阻塞开局。

## 历史与可观看回放

每局使用永久唯一 matchId，不使用可重复房间代码作为历史主键。独立档案保存参与者、起止时间、模式、难度、结局、到达回合、最终阵容、结果统计和版本，以及按回合分块的回放数据。房间清理不能删除对局档案。

记录各战场的初始输入、随机状态、阵容/装备/技能/朝向、按模拟 tick 排序的操作、动态共享状态及检查点；覆盖普通战斗、联防和最终攻势。保存休整期阵容快照供回合详情查看，本期不逐帧播放商店点击过程。

回放使用匹配 rulesVersion/dataVersion 的只读模拟与渲染入口，提供回合选择、参与者视角、暂停与 1×/2×/4×播放。保留已发布的版本化回放引擎及数据，不能用新版规则偷偷重算旧局。初版不承诺任意时间轴拖动或视频导出。

本人的对局记录及该局所有参与者可见；不提供公开分享和陌生玩家查询。回放 API 验证参与关系，不能仅凭 matchId 读取。列表分页、按时间排序，可筛选模式/难度/结果。

档案写入必须在 Match dispose 之前进入持久化待处理队列；结算、用户历史索引与统计更新使用 matchId 幂等键和可重试 outbox，重复完成事件不能重复计数。档案分块、按需读取，检查点与事件序列有完整性标记。回放不完整时显示不可播放原因，不能伪装成功。

对局结果和回放默认长期保留，不做静默过期删除。监控存储与写入量；容量不足时明确记录失败并保留已存档部分，不谎报历史保存成功。

## 统计口径

- 完成场次包括正常胜利和失败；中断、进行中、玩家提前离开单独列出，不纳入完成胜率。
- 胜率 = 完成胜场 / 完成场次；无完成场次显示“—”。按独立/同盟、难度筛选，隐秘核心通关独立计数。
- 最高回合使用已到达回合，并与已通过回合明确区分。
- 常用干员按出场对局数计算，同局重复出现只计一次；精锐合并到基础干员，排除召唤物。
- 复用已存在的 dmgDealt、healing、kills、leaks、bossDamage、perfectRounds、gold、refreshes、merges 等服务端结算字段；gold 显示为累计花费，不标成累计获得。
- 提前离开时保存该玩家截至离开的统计，不把后续 AI 数据算作其个人表现。AI 不建立个人账号统计。
- 统计由服务端已接受的游戏结果产生，沿用当前客户端战斗模型，不声称具备完整反作弊验证。历史事实可重新聚合，缓存统计有版本号。

## 服务边界与接口

### 持久性与恢复边界

DO 内存中的 JavaScript 对象会在休眠、驱逐或重启时丢失；只有写入 Storage API / SQLite 并成功提交的状态可依靠持久化恢复。实例长期不活跃不等于已存储数据过期，应用不得因房间租约过期清理独立历史档案。

SQLite DO 支持过去 30 天的时间点恢复（PITR）；这是恢复窗口，不是数据只保存 30 天。它不等于独立备份，也不能保证多个对象同时回退后仍一致。恢复工具须按 matchId 校验档案、个人索引和累计统计，优先从不可变档案重建派生数据。

应用误删、错误迁移、漏写数据、忽略存储失败或删除命名空间仍可能导致数据丢失。实施须测试提交前后中断、重复写入、恢复与清理隔离；失败操作不得返回已保存。提供版本化、可校验的档案与账号数据导出/导入工具，作为本期可验证的独立备份能力；默认不启用自动外部备份。若需要周期性异地备份，再配置独立存储目的地和调度，不能把 DO 的 PITR 宣称为永久灾备。

参考：https://developers.cloudflare.com/durable-objects/best-practices/access-durable-objects-storage/ 与 https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/。

- Worker：OAuth、cookie 校验、同源检查、公开 API 路由及可信身份转发。
- SiteDirectory DO：GitHub ID 到内部账号映射、会话定位、在线大厅租约；不保存战斗帧。
- Account DO：资料、会话撤销状态、当前席位声明、个人历史索引与统计。
- Room DO：房主权限、申请队列、席位与连接代次、Match 存档和自动恢复。
- MatchArchive DO：一局的不可变结算事实、版本化回放块与持久化发布状态。

计划接口：GET /api/auth/github/start、GET /api/auth/github/callback、GET /api/me、POST /api/auth/logout、GET /api/me/active-match、POST /api/me/resume、GET /api/me/matches、GET /api/me/stats、GET /api/matches/:id、GET /api/matches/:id/replay/:chunk、GET /api/rooms，以及房间申请的创建/取消/审批接口。所有历史接口分页或分块且有大小上限。OAuth 放在 /api 下以沿用现有 run_worker_first 匹配。

平台适配与业务规则分开。扩展共享协议和客户端状态，不把账号逻辑散落进战斗模拟模块。不修改现有战斗规则来迁就存储。

## 验收与实施顺序

1. 账号与可信身份：模拟 OAuth 成功、拒绝、state/PKCE 错误、重复回调、过期与退出，验证 WS 不能冒用账号。
2. 账号席位与对局持久化：两浏览器同账号恢复原席位、旧连接失效、每阶段实例重建、跨账号隔离、幂等事件和版本迁移。
3. 大厅与审批：在线/离线租约、公开/私密、AI 不算在线真人、并发抢最后席位、审批与开局竞争、超时/撤销/房主交接。
4. 归档与回放：每种战场录制后重播，核对关键检查点与最终结果；引擎更新后旧局仍可播放；重复结算和存储失败重试不重复统计。
5. 历史与统计 UI：筛选分页、空态、错误态、字段口径、个人数据隔离，以及现有页面视觉回归。
6. 运行相关测试、完整现有测试、Worker 构建和浏览器集成检查，再进行真实 GitHub 回调与双设备验收。模拟测试不能代替真实 OAuth 上线验证。

部署需要 GitHub OAuth App 的 Client ID/Secret 及站点回调配置。设计与本地实现不依赖提前提供 secret；真正配置时通过本机/平台 secret 输入，不写入仓库或设计文档。上线执行新增 DO migration，保留现有 ROOMS/ADMISSION 与域名配置，尊重 docs/CLOUDFLARE.md、wrangler.jsonc 当前已有未提交改动。
